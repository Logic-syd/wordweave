# 语境浏览器插件

Chrome / Edge 的 Manifest V3 插件。第一次转换需要你主动点击，支持当前文章或选中段落；在网页中阅读中文嵌词学习版、切换原文、查看词卡，并把收藏同步到语境网站。模型 API Key 始终保留在网站服务端。

## 安装与连接

1. 网站部署完成后，打开网站的 `/extension` 页面，下载并解压插件。
2. Chrome 打开 `chrome://extensions`（Edge 为 `edge://extensions`），开启开发者模式，选择「加载已解压的扩展程序」，选中包含 `manifest.json` 的文件夹。
3. 在网站环境变量中设置 `EXTENSION_ACCESS_TOKEN`，使用至少 32 个字符的随机值，并重新部署。可在自己的终端运行 `openssl rand -hex 32` 生成。不要使用模型 API Key 作为插件令牌。
4. 插件设置中填写网站地址和相同的插件访问令牌，点击「保存并授权连接」，再点击「测试连接」。只授权访问你填写的服务器。
5. 打开普通英文文章，点击工具栏中的语境小精灵，选择当前文章或选中段落。确认提取结果后点击「生成学习版」。

首次建议选一小节正文。生成后可以关闭弹窗或收起网页面板；关闭标签页也不会丢失已提交到网站的文章。生成失败会显示原因，只有主动重试才会重新调用模型。

## 本地开发

在仓库根目录运行：

```bash
npm ci
npm run extension:build
```

输出 `extension/dist/`（加载此文件夹）和 `public/downloads/wordweave-extension.zip`。构建完全使用本地打包的脚本，无远程执行代码。网站的 `npm run build` 也会先构建插件。

```bash
npx tsc --noEmit -p extension/tsconfig.json
npx eslint extension/src extension/scripts
```

本机测试可将服务器地址设置为 `http://localhost:3000` 或 `http://127.0.0.1:3000`。修改源码后重新构建，并在浏览器扩展页面点击「重新加载」，随后刷新文章页。

## 范围与隐私

- 支持普通英文文章的正文、标题、列表、链接、行内代码及代码块。代码不会交给模型改写。对动态站点采取保守处理；页面发生变化时跳过相关段落，避免覆盖网页的新内容。
- 最多 80 段、20,000 个 Markdown 字符，超出会提示选取较短内容，不会静默截断。
- 浏览器内置页面、扩展商店、本地文件、PDF、跨域 iframe 和需要复杂交互的应用界面不在第一版范围内。
- 默认不会自动翻译每个打开的页面，也不读取浏览历史。只有主动转换才上传提取的正文、标题、来源网址以及学习设置。
- 访问令牌保存在扩展自己的本地存储，内容脚本不能直接读取；内容脚本只通过限定的插件消息请求学习功能，网页脚本不能直接发送插件消息。后台不跟随 API 重定向。
- 最近 100 个任务仅缓存摘要、幂等键和任务编号，不持久缓存文章正文。相同内容、服务器、令牌和保留量复用任务；更换保留量或主动重试可能产生模型费用。
- 清除本地任务缓存不会删除网站文章和收藏，但之后相同正文可能重新生成。
- 第一版为个人站点配套插件，未发布到扩展商店，也不实现账号或多用户权限。

## 常见问题

**测试连接失败：** 确认网站能正常打开，已配置 `EXTENSION_ACCESS_TOKEN`，插件填写的值与网站完全一致，且已点击保存授权。地址只填写网站根地址，不带 `/read` 等路径。

**网站连接成功，但模型未配置：** 在网站服务端配置 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL` 后重新部署。不要把这些配置填进插件。

**网页没有识别到正文：** 选中一小节完整段落后重试。动态渲染页面、嵌入框架和编辑器可能无法可靠识别。

**浏览器提示由管理员禁止安装：** 受管理的浏览器可能不允许加载未打包插件，需要管理员允许或在你有权限管理的个人浏览器中安装。

## 验证

```bash
npm run typecheck
npm run lint
npm test                       # 含鉴权、幂等、任务及后台 worker 单元/数据库测试
npm run test:extension:dom     # Chromium 中测试提取、原位展示、恢复与词卡交互
npm run build
npm run test:extension         # 真正加载未打包扩展的本机端到端检查
```

`test:extension` 只允许使用 localhost PostgreSQL，并需要当前数据库账号有 CREATE DATABASE 权限。它创建独立临时数据库、应用迁移、启动独立 Next.js 服务和本地模型测试服务，结束后删除自己的临时数据库；不清空现有文章库。浏览器路径由 `CHROMIUM_PATH` 指定，默认 `/usr/bin/chromium`。测试模型是明确标识的夹具，不使用真实 API Key，不评价 DeepSeek 的语言质量。

如受管理的浏览器禁止加载扩展，可另外运行：

```bash
npm run test:extension -- --content-harness
```

这个模式在真实网页中运行打包后的内容脚本，通过测试消息桥接访问真实 HTTP 接口和临时 PostgreSQL，覆盖生成、收藏、原文恢复、重复请求和失败重试。它不验证扩展安装、浏览器原生权限弹窗或实际 MV3 生命周期，输出会明确标注模式。真实扩展模式在测试副本中仅增加 localhost 权限以便无头测试，不修改发布包；原生授权仍应手动检查。

本次云环境中：45 项单元/数据库测试、10 项 DOM 浏览器检查、9 项内容脚本与真实后端联调检查通过。云浏览器管理员策略禁止加载未打包扩展，因此完整安装与真实 DeepSeek 请求尚需在个人 Chrome/Edge 中完成一次验证。
